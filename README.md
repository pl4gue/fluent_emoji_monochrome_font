# Monochrome Fluent Emoji Build

Monochrome build of [fluent-emoji-webfont](https://github.com/tetunori/fluent-emoji-webfont/) font, based on Microsoft's [Fluent UI Emoji](https://github.com/microsoft/fluentui-emoji) glyphs.

The goal of this project is to produce a **single-color TrueType font** containing the Fluent Emoji glyphs, while preserving Unicode emoji sequences and ligatures.

The resulting font is intended for applications where the original multicolor Fluent Emoji font is unsuitable or where a monochrome emoji font is preferred.

## How it works

After inspecting the High Contrast fonts generated by [fluent-emoji-webfont](https://github.com/tetunori/fluent-emoji-webfont/), I decided to use its generated High Contrast SVGs as the source for a custom monochrome TrueType font.

The build process is split into two stages:

1. **`fluent-emoji-webfont` prepares the Fluent Emoji assets**
2. **`build_mono.py` converts those prepared SVGs into a monochrome TrueType font**

The repository keeps `fluent-emoji-webfont` as a Git submodule rather than copying its source into this repository.

### Source SVGs

The upstream project generates prepared High Contrast SVGs in:

```text
fluent-emoji-webfont/build/
```

These SVGs use the High Contrast Fluent Emoji artwork, which is already monochrome and uses the dark Fluent UI outlines/fills.

`build_mono.py` reads those SVGs and converts their `<path>` data into TrueType outlines.

The SVG coordinate system is transformed from the original 32×32 artwork into the font's 1024-unit-per-em coordinate system:

```text
x' = x * 37.5 + 37.5
y' = y * -37.5 + 950
```

This keeps the emoji artwork aligned with the metrics used by the original Fluent Emoji font.

### Unicode sequences

Fluent Emoji contains both individual Unicode codepoints and multi-codepoint emoji sequences.

For example:

```text
U+1F469 U+200D U+1F4BB
```

represents:

```text
👩‍💻
```

The corresponding glyph is named:

```text
u1F469_200D_1F4BB
```

`build_mono.py` creates OpenType `liga` substitutions so that sequences of Unicode glyphs are replaced by their corresponding Fluent Emoji glyph.

Conceptually:

```text
u1F469 u200D u1F4BB
        ↓ GSUB
u1F469_200D_1F4BB
```

This allows applications using a normal text shaping engine such as HarfBuzz to select the correct emoji glyph for multi-codepoint sequences.

Codepoints that only occur as components of sequences are also given invisible glyphs so that they can participate in the GSUB substitutions.

```text
.
```

The generated font is intentionally kept out of the source tree and placed under `dist/`.

## Building it

### Requirements

You need:

* Python 3
* `fonttools`
* `fluent-emoji-webfont` build dependencies
* `make`
* Git

On Arch Linux, the Python dependencies can be installed with:

```bash
python -m pip install --user fonttools
```

Depending on your environment, you may prefer a virtual environment.

### Clone

Clone the repository including the `fluent-emoji-webfont` submodule:

```bash
git clone --recurse-submodules <repository-url>
cd fluent-emoji-hc-mono
```

If the repository was cloned without submodules:

```bash
git submodule update --init --recursive
```

### Build

The complete build is performed through the Makefile:

```bash
make
```

This runs the upstream `fluent-emoji-webfont` preparation step and then builds the monochrome TrueType font.

The resulting font is:

```text
dist/FluentEmojiHighContrastMonochrome.ttf
```

### Rebuild from scratch

To remove generated upstream assets and the generated font:

```bash
make clean
```

Then:

```bash
make
```

This is useful when testing changes to either the upstream preparation process or `build_mono.py`.

## Building manually

The two stages can also be run independently.

First build the upstream SVG assets:

```bash
cd fluent-emoji-webfont
npm install
npm run build
cd ..
```

Then run:

```bash
python build_mono.py
```

The exact upstream commands may change as `fluent-emoji-webfont` evolves; the Makefile is the preferred interface for normal builds.

## Font characteristics

The generated font is a conventional TrueType outline font rather than a color emoji font.

The build intentionally does **not** generate or retain color font tables such as:

```text
COLR
CPAL
CBDT
CBLC
SVG
```

Instead, emoji artwork is stored in the standard TrueType `glyf` table.

The font uses:

```text
Units per em: 1024
Advance width: 1275
Ascent: 950
Descent: -250
```

The resulting font therefore behaves more like a normal monochrome text font than a platform-specific color emoji font.

## Why a separate build?

The original Fluent Emoji webfont project is designed around webfont generation and provides several font formats and styles.

This project has a narrower purpose:

* use the Fluent Emoji High Contrast artwork;
* convert it to standard TrueType outlines;
* keep the font monochrome;
* preserve Fluent Emoji Unicode sequences;
* avoid color emoji tables;
* produce a font that can be used anywhere a regular TTF font is accepted.

This also keeps the conversion logic independent from the upstream project's font-generation implementation.

## Upstream projects

This project would not exist without the following projects:

* [Microsoft Fluent UI Emoji](https://github.com/microsoft/fluentui-emoji) — source emoji artwork.
* [fluent-emoji-webfont](https://github.com/tetunori/fluent-emoji-webfont/) — preparation and webfont tooling used to generate the High Contrast SVG assets.
* [FontTools](https://github.com/fonttools/fonttools) — used to construct the TrueType font and compile OpenType features.
* [HarfBuzz](https://github.com/harfbuzz/harfbuzz) — useful for testing the resulting font's Unicode sequence shaping.

## Status

This project is primarily a personal build/conversion pipeline rather than a replacement for the upstream Fluent Emoji font.

The generated font should be considered **experimental**. The build currently prioritizes reproducing the Fluent Emoji High Contrast artwork and its Unicode sequence behavior over providing complete compatibility with every possible emoji-rendering environment.
